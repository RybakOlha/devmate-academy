# OR Learning Lab — пропозиція серверної архітектури

## Поточна версія
Сайт працює як статичний HTML/CSS/JavaScript на GitHub Pages. Бекенд не встановлено, реєстрації та серверного збереження немає. Для лабораторії DevMate браузер зберігає локальну чернетку, а Moodle залишається місцем здавання й оцінювання робіт.

## Рекомендований шлях — Moodle + окремий API за потреби
**Етап 1 (зараз):** залишити GitHub Pages для публічних матеріалів і практикумів. Використовувати Moodle для автентифікації учнів, завдань, оцінок і захищених персональних даних. Не створювати другу базу облікових записів без потреби.

**Етап 2 (коли потрібне серверне збереження прогресу):** створити окремий бекенд API, наприклад Python FastAPI + PostgreSQL. Розмістити API на окремому сервері/керованому хостингу з HTTPS, а фронтенд залишити на GitHub Pages. Базові маршрути: GET /api/courses, GET /api/courses/{slug}/modules, GET /api/me/progress, PUT /api/me/progress/{moduleId}. Ці маршрути — проєктна пропозиція, їх наразі не існує.

**Етап 3 (тільки за реальною потребою):** інтеграція з Moodle через дозволені механізми SSO/LTI або інший погоджений механізм. Не зберігати паролі Moodle у власній базі. Для ШІ-запитів застосовувати лише серверний проксі з ключами у змінних середовища, лімітами запитів та контролем доступу.

## Безпека та приватність
- GitHub Pages є публічним статичним хостингом: ніколи не публікувати секрети, API-ключі або персональні дані учнів у репозиторії.
- Для учнівських даних: визначити мету, строки зберігання, ролі доступу, резервне копіювання, правила видалення та правові підстави обробки до запуску бекенду.
- Перевіряти авторизацію на сервері для кожного запиту; обмежувати CORS конкретним доменом, додати rate limiting, журнали помилок без чутливих даних.
- Код учнів не виконувати безпосередньо на сервері без спеціально ізольованого середовища. Поточний Web Worker — навчальний механізм, не повна межа безпеки.

## Чому саме такий підхід
Він дозволяє поступово наповнювати всі п’ять курсів, не оплачувати сервер до появи реальної потреби та не дублювати функції Moodle. FastAPI + PostgreSQL — один із можливих стеків, не єдина допустима технологія. Альтернатива — Node.js (NestJS/Express) + PostgreSQL, якщо викладання бекенду планується на JavaScript.
